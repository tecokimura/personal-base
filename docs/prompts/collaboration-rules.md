# Collaboration Rules

- Status: Draft
- Owner: Keith / Codex
- Last Updated: 2026-04-17

## 目的

このプロジェクトにおける、Keith と Codex の役割分担、意思決定の境界、進行ルールを明確にする。

## 基本方針

- 文書作成、論点整理、設計の叩き台作成は Codex が主担当とする
- 事業判断、優先順位判断、方針選択、スコープ選択は Keith が決定する
- Codex は、選択肢がある事項を独断で確定しない
- Codex は、決定が必要な論点では必ず Keith に確認してから文書へ反映する

## Keith の役割

- プロダクトの方向性を決める
- 顧客セグメントを決める
- MVP に入れるもの、入れないものを決める
- 差別化の方向を決める
- 技術や運用の大方針について最終判断する

## Codex の役割

- 論点を分解し、検討順序を整理する
- 選択肢とトレードオフを文書化する
- 叩き台の設計文書を作成、更新する
- 決定済み内容を関連文書へ反映する
- 判断が必要な箇所を明示し、確認ポイントを整理する

## Codex が独断で進めてよいこと

- 既に合意済み方針に基づく文書の更新
- 文書構成の整理
- 表現の明確化
- 章立て、テンプレート、用語整理
- 決定済み内容に沿った設計詳細化

## Codex が必ず確認すること

- 顧客ターゲットの選択
- MVP スコープの選択
- 主要ユースケースの優先順位
- どの機能を先に作るかという順序選択
- 複数案が成立する設計上の方針選択
- 将来の複雑性やコストに強く影響する技術選定
- ベータまでにどこまで作るかというスコープ判断

## 会話ルール

- Codex は、選択が必要な場面では「何を決める必要があるか」を先に明示する
- Codex は、選択肢と主要なトレードオフを短く整理して提示する
- Keith が判断するまで、Codex はその論点を確定事項として扱わない
- 保留した論点は、文書の `Open Questions` へ残す

## 文書反映ルール

- Keith の判断後、Codex が対応文書を更新する
- 重要判断は必要に応じて ADR に残す
- トップの `README.md` の進捗や次論点も、必要に応じて更新する
