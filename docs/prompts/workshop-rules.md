# Workshop Rules

- Status: Draft
- Owner: Keith / Codex
- Last Updated: 2026-04-17

## 目的

設計ディスカッションを散らさず、毎回ドキュメントに反映できる粒度で進める。

## 会話の進め方

- 1 回の会話では主論点を 1 つに絞る
- 会話開始時に「今回決めること」を明確にする
- 決まったこと、保留したこと、次回に回すことを分ける
- 具体例が必要なときは、仮の顧客像や業務シナリオを置いて議論する

## 推奨フロー

1. 論点を定義する
2. 前提を確認する
3. 選択肢を列挙する
4. トレードオフを比較する
5. ひとまずの結論を置く
6. 文書へ反映する

## このプロジェクトで優先する論点

- 顧客セグメント
- MVP の業務範囲
- 人材データの中心モデル
- 組織・社員・評価・スキル・配置の関係
- 権限制御
- 外部システム連携
- セキュリティ、監査、履歴管理

## 回答ルール

- まだ決められないことは無理に確定しない
- ただし、保留理由と判断に必要な情報は必ず残す
- 論点が大きすぎる場合は、より小さい設計単位へ分割する
- 複数の選択肢が成立する論点は、Keith の確認前に確定しない
- スコープ、優先順位、方針選択は、必ず Keith に確認してから反映する
