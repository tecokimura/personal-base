# Document Rules

- Status: Draft
- Owner: Keith / Codex
- Last Updated: 2026-04-17

## 目的

設計ドキュメントの書き方を統一し、後から見ても理解できる状態を維持する。

## 基本ルール

- 1 文書 1 主題を守る
- 推測、仮説、確定事項を混ぜない
- 決定の理由を省略しない
- 主観的な言い回しより、業務上・技術上の事実を書く
- 文書の冒頭に `Status`, `Owner`, `Last Updated` を置く

## 必須セクション

原則として、各設計ドキュメントには次を含める。

- `目的`
- `背景`
- `前提`
- `決定事項`
- `検討した選択肢`
- `Open Questions`
- `次に決めること`

## 記述ルール

- 要件は「誰が、何のために、何をできる必要があるか」で書く
- 非機能要件は、可能な限り測定可能に書く
- 技術選定は、採用理由と不採用理由の両方を書く
- 表現が曖昧な語は避ける
- 一時的なメモではなく、将来の判断材料として読める形にする

## 禁止事項

- 結論のない長文メモを本文に残す
- 未確定事項を確定事項のように書く
- 重要な設計変更を、理由なしで既存文書へ反映する

## 更新ルール

- 重要な方針変更は `docs/decisions/` に ADR を追加する
- 更新したら、必要に応じてトップの `README.md` の現在地も更新する
