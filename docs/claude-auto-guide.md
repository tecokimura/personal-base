# claude-auto パイプライン 課題起票ガイド

- Status: Active
- Owner: Keith
- Last Updated: 2026-06-07

このドキュメントは、claude-auto パイプラインを使って実装を自動化する際に、
Backlog 課題を正しく起票するためのガイドです。

---

## 基本の流れ

```
1. 課題を起票する（カテゴリなし・仕様検討中）
2. 説明・完了条件を書き込む
3. 仕様が固まったら「実装待ち」カテゴリを付ける
4. パイプラインが自動で拾って実装を開始する（最大30分以内）
5. 急ぎの場合は手動実行: ./claude-auto/pipeline.sh
```

---

## 課題の粒度（最重要）

実装セッションは1回で完結します。**大きすぎる課題はトークン切れで途中停止します。**

| 粒度 | 例 | 判定 |
|---|---|---|
| 大きすぎ | 「社員アカウント管理機能」 | ❌ |
| 適切 | 「HR_ADMIN が社員に UserAccount を発行する API」 | ✅ |
| 適切 | 「アカウント発行画面（フロントエンド）」 | ✅ |

**目安: 1〜2画面、または 1 API エンドポイント単位**

大きな機能は以下のように分割してください：
- 親課題（管理・追跡用・カテゴリなし）
- 子課題①（API 実装・「実装待ち」）
- 子課題②（フロント実装・「実装待ち」）

---

## 必須記載項目

### 件名
機能が一目でわかる名前にする。

```
例: HR_ADMIN による社員 UserAccount 発行 API
例: 社員詳細画面にアカウント発行ボタンを追加
```

### 説明
以下を必ず書く：

```
## 背景
なぜこの機能が必要か

## 要件
- 箇条書きで具体的に

## 完了条件
- テストが通ること
- 〇〇画面で△△できること
- Backlog コメントに動作確認手順を記載すること

## 関連
- 参照する設計ドキュメント（docs/ のパス）
- 関連課題番号
```

**完了条件が曖昧だと実装セッションが「仕様確認待ち」で止まります。**

---

## カテゴリの使い方

| カテゴリ | いつ付けるか |
|---|---|
| （なし） | 仕様検討中・まだ実装させたくない |
| `実装待ち` | 仕様確定・実装開始してよい状態 |
| `レビュー待ち` | パイプラインが自動で付ける（手動設定不要） |
| `修正待ち` | パイプラインが自動で付ける（手動設定不要） |
| `動作確認待ち` | パイプラインが自動で付ける（手動設定不要） |
| `仕様確認待ち` | パイプラインが止まって確認を求めている状態 |

**「実装待ち」を付けると最大30分以内にパイプラインが拾います。**

---

## 動作確認コメントの書き方

課題が「動作確認待ち」になったら、あなたがコメントを入れるまでパイプラインは待機します。

### OK の場合
```
動作確認しました。問題ありません。
```

### 修正依頼の場合
```
以下の修正をお願いします。
- △△画面で〇〇をすると××になる（期待動作: □□）
- □□の文言を「〇〇」に変更してください
```
→ パイプラインが新規課題を自動起票して元課題を完了にします。

---

## 手動トリガー

課題に「実装待ち」を付けた後、すぐに処理を始めたい場合：

```bash
./claude-auto/pipeline.sh
```

また、idle バックオフ中に強制再開したい場合：

```bash
rm -f claude-auto/logs/idle-backoff.txt
./claude-auto/pipeline.sh
```

## ブランチ運用

- 実装セッションは課題ごとに `feat/PMO_PJPERSONALBASE-XX` ブランチを作成します
- `develop` ブランチに直接コミットしません
- レビュー OK 後に PR を作成し `develop` にマージします
