# claude-auto パイプライン 課題起票ガイド

- Status: **再設計中**（旧cronパイプラインは削除済み。このドキュメントの「パイプラインが自動で拾う」等の記述は旧方式のもので、現在は該当する自動実行の仕組みはありません）
- Owner: Keith
- Last Updated: 2026-08-24

このドキュメントは、claude-auto パイプラインを使って実装を自動化する際に、
Backlog 課題を正しく起票するためのガイドです。

課題の粒度・必須記載項目・カテゴリの意味など、**Backlog起票のルール自体は引き続き有効**です。
「パイプラインが自動で拾う」「30分以内」等の記述は旧cronオーケストレーター前提のもので、
現時点では対話セッション（loopスキル等）で1件ずつ手動トリガーする方式に置き換え中です。

---

## 基本の流れ（現行）

```
1. 課題を起票する（カテゴリなし・仕様検討中）
2. 説明・完了条件を書き込む
3. 仕様が固まったら「実装待ち」カテゴリを付ける
4. 対話セッションで claude-auto/impl.sh <課題キー> を実行して実装する
5. 完了後 claude-auto/review.sh <課題キー> でレビューする
```

---

## 課題の粒度（最重要）

実装セッションは1回で完結します。**大きすぎる課題はトークン切れで途中停止します。**

| 粒度 | 例 | 判定 |
|---|---|---|
| 大きすぎ | 「社員アカウント管理機能」 | ❌ |
| 適切 | 「HR_ADMIN が社員に UserAccount を発行する API」 | ✅ |
| 適切 | 「アカウント発行画面（フロントエンド）」 | ✅ |

**目安: 1〜2画面、または 1 API エンドポイント単位**

大きな機能は以下のように分割してください：
- 親課題（管理・追跡用・カテゴリなし）
- 子課題①（API 実装・「実装待ち」）
- 子課題②（フロント実装・「実装待ち」）

---

## 必須記載項目

### 件名
機能が一目でわかる名前にする。

```
例: HR_ADMIN による社員 UserAccount 発行 API
例: 社員詳細画面にアカウント発行ボタンを追加
```

### 説明
以下を必ず書く：

```
## 背景
なぜこの機能が必要か

## 要件
- 箇条書きで具体的に

## 完了条件
- テストが通ること
- 〇〇画面で△△できること
- Backlog コメントに動作確認手順を記載すること

## 関連
- 参照する設計ドキュメント（docs/ のパス）
- 関連課題番号
```

**完了条件が曖昧だと実装セッションが「仕様確認待ち」で止まります。**

## カテゴリの使い方

| カテゴリ | いつ付けるか |
|---|---|
| （なし） | 仕様検討中・まだ実装させたくない |
| `実装待ち` | 仕様確定・実装開始してよい状態 |
| `レビュー待ち` | 実装セッション（`impl.sh`）が完了時に付ける（手動設定不要） |
| `修正待ち` | レビューNG時にPMセッションが付ける（手動設定不要） |
| `動作確認待ち` | レビューOK時にPMセッションが付ける（手動設定不要） |
| `仕様確認待ち` | 実装/レビューセッションが止まって確認を求めている状態 |

**現在「実装待ち」を付けても自動では拾われません。** 対話セッションで `impl.sh <課題キー>` を実行してください。

---

## 動作確認の進め方（現行）

課題が「動作確認待ち」になったら、あなたが実際に動かして確認し、対話セッション（PMセッション）にその場で結果を伝えます。

### OK の場合
チャットで「動作確認できました、完了にしてください」等と伝える → PMセッションがBacklogを「完了」に更新します。

### 修正依頼の場合
チャットで不具合内容を伝える → PMセッションが新規課題を起票、または既存課題を「修正待ち」に戻します。

## 手動トリガー

```bash
cd /home/keith/Documents/projects/personal-base
./claude-auto/impl.sh PMO_PJPERSONALBASE-XX     # 実装
./claude-auto/review.sh PMO_PJPERSONALBASE-XX   # レビュー
```

いずれもヘッドレス実行（`claude -p`）のため、実行前に内容を把握した上で使ってください。
対話的に進めたい場合は、スクリプト内のプロンプトをそのままこのセッションに貼って実行することもできます。

## ブランチ運用

- 課題ごとに `feat/pmo-{課題番号}-{スラグ}` ブランチを作成します（スラグは小文字英数字とハイフンのみ、最大30文字）
- `feat/phase3`（現行フェーズブランチ）に直接コミットしません（`.claude/hooks/guard-git.sh` でブロックされます）
- レビュー OK 後に PR を作成し、フェーズブランチにマージします（マージは人間のみ）
