# Roadmap And Milestones

- Status: Draft
- Owner: Keith / Codex

## 目的

この文書は、プロジェクト全体のゴール、現在地、フェーズ、マイルストーンを一枚で把握できるようにするための進行管理ハブである。

人間の担当交代、別 AI への引き継ぎ、同じ AI のセッション再開時にも、この文書を見れば「何を目指していて、今どこで、次に何を決めるか」が分かる状態を目指す。

## 背景

このプロジェクトは、カオナビやタレントパレットのようなタレントマネジメントサービスを、必要機能を絞ってベータへ早く到達する方針で設計している。

ただし、設計論点が多いため、`MVP`、`第2フェーズ`、`将来拡張` が混ざると全体像を見失いやすい。そこで、段階ごとのゴールと判断対象を明確に分けて管理する。

## 前提

- 初期ターゲットは `100 名から 500 名規模の企業`
- 主担当ユーザーは `人事部門 + 管理職`
- 経営層は初期フェーズでは閲覧中心
- MVP の中心ユースケースは `社員台帳と組織図の一元管理`
- 一般社員向け機能は将来重要だが、最初から全部は入れない
- スコープや優先順位の確定は必ず Keith に確認する

## ゴール

### 最終的に目指すプロダクト

- 人材情報を単に保存するのではなく、組織内の意思決定に使える状態へ整える
- 人事、管理職、一般社員が、権限に応じて人材情報を閲覧・更新できる
- 将来的に、業務履歴やスキル情報から AI が要約や助言を行える

### 直近の到達目標

- ベータに到達できる最小スコープを定義する
- そのベータを実装可能な粒度まで、プロダクト設計と技術設計を固める

## 現時点の確定事項

- 初期ターゲットは `100 名から 500 名規模の企業`
- 主担当ユーザーは `人事部門 + 管理職`
- MVP は `社員台帳と組織図の一元管理`
- 中心モデルは `Employee`, `Organization`, `Employment`, `RoleAssignment`, `OrganizationLeader`
- 兼務は `Employment` の複数レコードで扱う
- 兼務は別組織所属よりも、同一組織内の役割兼任や案件兼務を中心に扱う
- 権限モデルは `RBAC + 組織スコープ`
- `ORG_ADMIN` は役職と独立したロール
- 顔写真は本番でオブジェクトストレージ、開発でローカルファイル保存も許容
- 履歴は `Employment` と `OrganizationLeader` を中心に持つ
- 論理削除社員の閲覧・復元は `ORG_ADMIN` のみ
- `profile_free_text` は MVP に含める
- `WorkHistory` は第 2 フェーズで導入し、完成形では必須機能とする
- `WorkHistory` は本人に加えて `HR_ADMIN` と `MANAGER` が補助編集できる
- `WorkHistory` は同僚も閲覧できる前提とする
- `WorkHistory` は最初から `updated_by` を持つ
- `LoginHistory` と `EditHistory` は第 2 フェーズ前半で導入する推奨とする
- マルチテナント方式は、共有テーブル型を基本にしつつ、単一テナント専用デプロイにも対応できる方式を第一候補とする
