# Requirements

- Status: Draft
- Owner: Keith / Codex
- Last Updated: 2026-04-17

## 目的

機能要件と非機能要件の整理方針を定義する。

## 背景

早い段階で要件の枠組みを持たないと、機能の追加議論が無制限に増えやすい。

## 前提

- MVP と将来拡張を分けて考える
- 完成形では `WorkHistory` が必須機能になる

## 決定事項

- MVP では `社員台帳と組織図の一元管理` を中心とする
- `Employee` には `profile_free_text` を持たせる
- `profile_free_text` は自己紹介または業務概要を自由に書ける複数行テキストとする
- `profile_free_text` は本人に加えて `HR_ADMIN` と `MANAGER` が補助更新できる
- MVP ではまずプレーンテキスト入力を前提とする
- Markdown はオプション機能として `profile_free_text` に限って第 2 フェーズで扱う
- 第 2 フェーズでは Markdown を含む入力を保存できればよく、表示は生テキストのままでよい
- Markdown のレンダリング表示は第 3 フェーズ以降の拡張候補とする
- `WorkHistory` は MVP 外だが、完成形では必須機能とする

## 機能要件の現時点整理

### MVP に含める機能

- 社員台帳の登録、更新、閲覧
- 組織図の閲覧
- ロールと組織スコープに基づく権限制御
- 顔写真の登録と表示
- `profile_free_text` の登録、更新、表示

### MVP では含めないが必須とする後続機能

- `WorkHistory` の複数件登録、更新、閲覧

理由:

- 社員が自分のこれまでの仕事や履歴を管理、確認できるようにするため
- 将来の AI 要約や検索の元データとして必要なため

### `WorkHistory` の最小要件たたき台

- 社員本人が自分の履歴を複数件登録できる
- `HR_ADMIN` と `MANAGER` が補助編集できる
- 各履歴に `社員参照`、`年月の期間`、`業務内容`、`開発環境やツール`、`役割`、`規模` を持てる
- 現在進行中の履歴を表現できる
- `規模` は開発チーム人数の数値として持つ
- 社内運用向けに `プロジェクトコード` を自由入力で持てる余地を残す
- 各履歴に `updated_by` を持ち、最終更新者を追えるようにする
- 各履歴に `updated_at` を持ち、最終更新時刻を追えるようにする
- 自分自身は全件閲覧できる
- 同僚も `WorkHistory` を閲覧できる前提とする
- 第 2 フェーズではレコード単位の公開/非公開切替を持たず、同僚公開は一律ルールで扱う
- 同僚にも `WorkHistory` の AI サマリを表示できる前提とし、本人以外にも公開してよい情報として扱う
- 同僚には、直近 `1 年 (365 日)` までは `WorkHistory` の原文をそのまま表示し、それ以前は AI サマリを表示する
- 原文表示の直近期間は、システム設定または管理者向けサービス設定で変更できるようにする
- AI サマリは、登録者本人のこれまでの業務内容を要約し、他者にスキルをアピールできる文章を生成する目的で使う
- AI サマリは MVP や第 2 フェーズの必須対象には置かず、第 3 フェーズ以降の拡張候補とする
- AI サマリは都度生成ではなく、`WorkHistory` の登録または更新時に再生成する前提とする
- AI サマリは、事前に決めた文字数内の文章に加えて、利用ツール・技術の一覧を出力できる形を目指す
- AI サマリの文字数は固定値ではなく設定値で持ち、実装後に調整できるようにする
- 初期推奨値として、キャリアサマリは `180〜280 文字`、スキルアピール文は `70〜120 文字` を目安にする
- ツール・技術一覧は、まずカテゴリ別の一覧表示を第一候補とする
- AI サマリの表示順は、`キャリアサマリ` → `スキルアピール文` → `ツール・技術一覧` を第一候補とする
- 本人、`HR_ADMIN`、`MANAGER` は、設定期間ごとのページングで全件の原文を閲覧できるようにする
- `WorkHistory` は将来の履歴書出力を見据え、自由装飾よりも構造化入力を優先する
- そのため、Markdown は `profile_free_text` 側では検討余地があるが、`WorkHistory` では慎重に扱う
- `organization_name_snapshot`、`visibility_scope`、`sort_order`、`created_by` は第 2 フェーズの最小項目からは外す
