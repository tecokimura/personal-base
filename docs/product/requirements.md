# Requirements

- Status: Draft
- Owner: Keith / Codex

## 目的

機能要件と非機能要件の整理方針を定義する。

## 背景

早い段階で要件の枠組みを持たないと、機能の追加議論が無制限に増えやすい。

## 前提

- MVP と将来拡張を分けて考える
- 完成形では `WorkHistory` が必須機能になる

## 決定事項

- MVP では `社員台帳と組織図の一元管理` を中心とする
- `Employee` には `profile_free_text` を持たせる
- `profile_free_text` は自己紹介または業務概要を自由に書ける複数行テキストとする
- MVP ではまずプレーンテキスト入力を前提とし、Markdown は将来拡張候補とする
- `WorkHistory` は MVP 外だが、完成形では必須機能とする

## 機能要件の現時点整理

### MVP に含める機能

- 社員台帳の登録、更新、閲覧
- 組織図の閲覧
- ロールと組織スコープに基づく権限制御
- 顔写真の登録と表示
- `profile_free_text` の登録、更新、表示

### MVP では含めないが必須とする後続機能

- `WorkHistory` の複数件登録、更新、閲覧

理由:

- 社員が自分のこれまでの仕事や履歴を管理、確認できるようにするため
- 将来の AI 要約や検索の元データとして必要なため

### `WorkHistory` の最小要件たたき台

- 社員本人が自分の履歴を複数件登録できる
- `HR_ADMIN` と `MANAGER` が補助編集できる
- 各履歴に `年月の期間`、`業務内容`、`開発環境やツール`、`役割`、`規模` を持てる
- 現在進行中の履歴を表現できる
- `規模` は開発チーム人数の数値として持つ
- 社内運用向けに `プロジェクトコード` を自由入力で持てる余地を残す
- 各履歴に `updated_by` を持ち、最終更新者を追えるようにする
- 自分自身は全件閲覧できる
- 同僚も `WorkHistory` を閲覧できる前提とする
- 将来は、直近 `半年から 1 年` 程度は原文を表示し、それ以前は AI 要約を表示する方針を検討する
- 原文表示の直近期間は、システム設定または管理者向けサービス設定で変更できるようにする
