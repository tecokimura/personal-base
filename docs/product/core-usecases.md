# Core Use Cases

- Status: In Review
- Owner: Keith / Codex
- Last Updated: 2026-04-17

## 目的

MVP で優先すべき業務シナリオを定義する。

## 背景

機能から入ると対象範囲が広がりすぎるため、まずは業務シナリオで優先順位をつける。今回のプロジェクトでは、100 名から 500 名規模の企業を対象に、必要機能を絞って早くベータへ到達する方針を取る。

## 前提

- MVP ではすべての人事機能を扱わない
- 初期ターゲットは `100 名から 500 名規模の企業`
- 主担当ユーザーは `人事部門 + 管理職`
- 経営層は初期フェーズでは閲覧中心
- 一般社員は、自分のスキル、業務履歴、および一定範囲の同僚の業務履歴を閲覧できる体験を重要視する
- 人材データ基盤を先に整え、その上に高度な機能を積み上げる方針を第一候補とする

## 決定事項

- MVP の中心ユースケースは `社員台帳と組織図の一元管理` とする
- 後続の優先順位は `人材プロフィールの更新・自己申告` を先、`評価情報の集約と閲覧` を後とする
- MVP は「人材データの集約、検索、閲覧」に直結する業務を優先する
- 評価運用のフル機能や配置検討の高度機能は、初期候補から外す

### この判断の理由

- まずは最小のスコープで実装に入ることを優先する
- `社員台帳と組織図` は後続のスキル、履歴、評価、権限制御の前提になる
- `人材プロフィール更新` と `評価情報閲覧` は重要だが、初手の MVP からは切り離した方がベータ到達しやすい

## 検討した選択肢

### 1. 社員台帳と組織図の一元管理

業務シナリオ:

- 人事が社員基本情報、所属、役職、雇用区分を一元管理する
- 管理職が自組織のメンバー構成を閲覧する
- 経営層が組織全体を閲覧する

MVP への適合:

- 非常に高い
- 後続のすべての機能の前提になる

### 2. スキル、経験、資格、業務履歴の検索・閲覧

業務シナリオ:

- 人事が条件で人材を検索する
- 管理職がメンバーや候補者のスキル・経験を確認する
- 一般社員が自分のプロフィールと業務履歴を確認する
- 一般社員が一定範囲の同僚の業務履歴を閲覧する

MVP への適合:

- 非常に高い
- このサービスの差別化の軸になりやすい

### 3. 人材プロフィールの更新・自己申告

業務シナリオ:

- 人事が社員情報を初期投入する
- 社員本人がスキル、資格、経歴、自己紹介などを更新する
- 管理職や人事が更新内容を確認する

MVP への適合:

- 高い
- データが育たない問題を避けるために有効

### 4. 評価情報の集約と閲覧

業務シナリオ:

- 人事が過去評価結果を蓄積する
- 管理職がメンバーの評価履歴を参照する
- 経営層が評価分布を閲覧する

MVP への適合:

- 中程度
- 「評価運用」を含めると重くなるが、「評価結果の参照」に絞れば候補になりうる

### 5. 評価ワークフローの運用

業務シナリオ:

- 評価シート配布
- 一次評価、二次評価、調整、確定
- 面談記録やコメント収集

MVP への適合:

- 低い
- ワークフロー要件が企業ごとにぶれやすく、ベータを遅らせる可能性が高い

### 6. 配置検討と後継者管理

業務シナリオ:

- 候補人材の比較
- 後継候補一覧の管理
- 異動シミュレーション

MVP への適合:

- 低い
- 基盤データと権限制御が整ってからでないと品質を出しにくい

### 現時点の有力候補

ベータ優先の方針に照らすと、業務領域の優先順位は以下とする。

- 社員台帳と組織図の一元管理
- 人材プロフィールの更新・自己申告
- 評価情報の集約と閲覧

このうち、MVP に含めるのは `社員台帳と組織図の一元管理` のみとする。

`スキル、経験、資格、業務履歴の検索・閲覧` は重要な業務領域だが、現時点では `社員台帳と組織図` の上に積む次段階の候補として扱う。

### MVP から外す候補

現時点では、以下は MVP 対象外候補とする。

- 評価ワークフローの運用
- 配置検討と後継者管理
- 高度な分析ダッシュボード
- AI による助言機能

これらは将来拡張としては重要だが、現段階ではデータ基盤と権限設計を先に固めるべき。

## Open Questions

- 一般社員による同僚業務履歴の閲覧を、MVP の主要ユースケースに含めるか
- 人材プロフィール更新を、社員自身の自己申告中心にするか、人事主導中心にするか
- `スキル、経験、資格、業務履歴の検索・閲覧` を第 2 フェーズのどこで入れるか

## 次に決めること

- `社員台帳と組織図` の具体的な対象データ項目
- 組織図と権限の基本ルール
- 第 2 フェーズに入れるユースケース
