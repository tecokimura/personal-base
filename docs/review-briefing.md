## プロジェクト概要

カオナビ・タレントパレットのようなタレントマネジメントサービスを、**必要機能を絞ってベータへ早く到達する**方針で個人開発しています。

- **最終ゴール**：人材情報を「蓄積する場所」ではなく「組織の意思決定に使える基盤」にする
- **初期ターゲット**：100〜500名規模の企業。主ユーザーは人事部門と管理職
- **技術スタック**：NestJS（バックエンド）+ Next.js（フロントエンド）+ PostgreSQL + Prisma。マルチテナント構成

## 開発体制・自動化パイプラインについて

実装は Claude Code（AI）を cron で定期実行する **claude-auto パイプライン**で半自動化しています。

```
cron 実行
  → 診断フェーズ（Backlog の未対応課題を確認）
  → 実装フェーズ（Claude が実装・テスト・コミット）
  → レビューフェーズ（別セッションの Claude がコードレビュー）
  → 動作確認（人間が確認・Backlog にコメント → 完了）
```

人間（自分）が介入するのは主に「仕様判断」「動作確認」「方向性の確認」の3点です。

## フェーズ 4 に向けた設計上の重要な決定事項

フェーズ 4（AI 拡張）に備えてすでに設計上の方針を固めています。

- **WorkHistory**（業務履歴）は第 2 フェーズで実装済み。項目は `yearMonthFrom/To`, `workSummary`, `toolsUsed`, `roleName`, `teamSize` など
- **AI サマリ**は WorkHistory 登録・更新時に再生成する方式。キャリアサマリ（180〜280文字）＋スキルアピール文（70〜120文字）＋ツール一覧
- **閲覧ルール**：同僚は直近1年の原文＋それ以前はAIサマリを表示（フェーズ 4 以降）
- **AI 機能の優先順位**：AI 検索・推薦 → AI アドバイス文 → AI 相談チャット

## 補足：詳細な仕様が必要な場合

リポジトリが見えない場合でも、以下の観点で詳細を共有できます。

- **権限モデル**：RBAC + 組織スコープ。ロールは HR_ADMIN / MANAGER / ORG_ADMIN / EXECUTIVE_VIEWER / EMPLOYEE の5種
- **データモデル**：Employee / Organization / Employment / RoleAssignment / OrganizationLeader / WorkHistory が中心エンティティ
- **認証**：アプリ内認証（メール+パスワード）+ 2FA（TOTP）。SSO はフェーズ 3 以降の候補
- **マルチテナント**：共有テーブル型。`tenant_id` を全主要テーブルに持つ
